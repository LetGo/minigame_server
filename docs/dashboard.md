## 统计口径

- 北京时间自然日（Asia/Shanghai，00:00 切日）。
- **今日活跃**：今天成功完成游戏登录的用户去重。仅持旧 token 拉取/保存存档、上报 scene 或查邀请不算登录活跃；不是在线人数。
- **今日新注册**：注册时间落在今天、首次登录已成功完成的用户。
- **今日邀请新注册 / 每日其中邀请注册**：上述新注册用户中，已存在本游戏成功绑定邀请关系的去重人数；按注册日期（北京时间）归属，不按绑定/领奖日期计数，与是否领奖无关。延迟绑定会在下一次刷新补到原注册日；尚未上报绑定的用户暂不计入，剩余人数不能直接当作确定的自然新增。卡片同时显示占今日新注册比例，趋势每行在人数后显示 `人数（XX.XX%）`，比例 = 该行日期邀请注册人数 ÷ 该行日期新注册人数（不是所有历史行除以今天新增）；分母为 0 或数据不可用显示“—”。现有表只读查询，无需迁移或改游戏 API。
- **今日激励视频次数**：按数据库服务端 `recorded_at` 统计北京时间当日 `[00:00, 次日00:00)` 已保存的完整观看事件，跨点位及玩家；同一玩家同一事件 ID 重试不重复计数，不是观看人数或广告平台核验数据。不展示历史累计数，历史明细仍保留，跨日自动按新一天查询，无需清表或定时重置。客户端接入后才有数据，不补造历史。详见 [`rewarded-video-api.md`](rewarded-video-api.md)。删除玩家会级联移除其事件。卡片说明显示 **人均次数 = 今日激励视频次数 ÷ 今日活跃用户数**（包含未观看视频的活跃用户），保留两位小数；活跃人数为 0 或任一指标不可用时显示“—”，有活跃但视频次数为 0 时显示 `0.00`。
- **近 14 天趋势 · 激励视频次数**：接口 `history[].rewardedVideos` 按每行日期的北京时间 `[00:00, 次日00:00)`，统计现有 `game_rewarded_video_events.recorded_at` 上报事件；与今日卡片同一来源、同一去重口径，跨玩家及点位累计，不是观看人数。今天行与今日卡片数值一致、随刷新更新；不随次留移到注册日，也不受登录活跃覆盖日期限制。无上报记录显示 `0`，不代表实际未观看；未接入前的历史不推算、不补造。接口字段不可用时前端显示“—”。趋势在次数后追加 `（人均 X.XX 次）`，人均 = 该行日期的视频次数 ÷ 该行日期登录活跃人数（包含未观看的活跃用户）；有活跃且视频为 0 时显示 `0.00`，活跃人数为 0、未覆盖或任一指标缺失时人均显示“—”。保留原始总次数与 7 列结构，纯展示计算，不改接口、SQL 或历史数据。
- **注册用户视频数（开发完成，尚未发布）**：概览近 14 天趋势在「激励视频次数」后新增一列，接口字段 `history[].registeredUserVideos`。日期 D 行统计本游戏在北京时间 D 日完成注册的用户、在 D 日 `[00:00, 次日00:00)` 上报完成的激励视频事件数；只计首次登录已完成用户，事件不得早于其注册时间，不含老用户、其他游戏或该队列在以后日期的观看，不是新用户历史累计。保留事件 ID 去重口径，不按观看人数计数。显示 `次数（人均 X.XX 次）`，人均 = 该行注册用户视频数 ÷ 该行新注册人数（包含零观看的新用户），两位小数；正分母零视频显示 `0（人均 0.00 次）`，零分母或字段缺失时人均为 `—`。原视频列仍除以当日 DAU，两列分母不同。趋势扩为 8 列，六张顶卡、日期倒序、周末绿色、次留及缓存口径不变。仅只读查询与前端展示，无迁移、玩家写入或游戏 API 变更；与待发布的 openid 筛选分开记录，未经另行授权不部署。
- **实时次留**：昨日新注册用户中，今天已经成功登录的用户数 ÷ 昨日新注册人数。当天持续变化，不是最终整日次留。分母为 0 显示“—”。
- 最近 14 天趋势的**次日留存按注册日期归属**：日期 D 这一行显示 D 日新注册用户在 D+1 日成功登录的人数 ÷ D 日新注册人数，“次日回访 / 当日新增”也使用同一批用户。新增及 DAU 仍属于该行当天，不平移其他指标。今天这一行的次留及回访数显示“待次日统计”；昨日这一行标记“实时”，随今日回访更新，今日结束后为整日值。顶部实时次留卡片仍使用昨日新增、今日回访。接口 history 保留 date 为注册日期，cohortSize 等于该行 newUsers，retentionDate 是次日日期，d1Pending 标记尚未进入次日的今日队列；未到次日时 returned/d1Rate 为 null。今天日期标记“截至现在”。页面每 30 秒刷新，隐藏页面暂停轮询。
- **更新于**：接口 `generatedAt` 是本次统计查询开始时的数据库服务端时间，与 `today` 及当日统计边界共用同一时间快照，前端按北京时间显示。缓存命中时保持原值，缓存失效并成功重新统计后更新；不是最新玩家操作时间，也不是代码发布时间。

- `005_daily_logins.sql` 建立逐日登录表。上线当日用用户现有 `last_login_at` 补录当日已登录用户，**不使用最后登录时间反推更早每日活跃**。覆盖日期前的 DAU 显示“—”；次留按**次日回访日**是否达到覆盖日期判断，未覆盖或分母为 0 显示“—”，不把未知回访当成 0。注册日早于覆盖日期、但其次日在覆盖范围内的队列仍可统计次留。历史注册数仍可查询。覆盖日期由数据库记录，非前端猜测。
- 登录与当天去重记录在同一数据库事务中提交；Redis/数据库失败不得留下成功活跃或半注册记录。按获锁后数据库时钟归日，跨日不使用排队前的事务起始时间。

## 概览性能与缓存

- 概览使用服务端进程内缓存，按游戏和北京时间日期隔离，最多保留一个快照；当前单实例的所有已登录管理员页面共享。TTL 最多 30 秒，从实际查询开始时间/`generatedAt` 计，不从查询完成或每次命中续期；北京时间零点提前失效。
- 缓存未命中或过期时，同一实例的并发请求共享同一次统计查询（single-flight）。旧日查询若跨零点才返回，丢弃旧日结果并合并重查；持续日期不一致时返回脱敏 503，不循环、不展示昨日数值。数据库错误不缓存，也不使用过期快照兜底。
- 每次请求仍先校验 Redis 登录会话；缓存命中也不跳过鉴权，退出/会话过期/Redis 故障均不能读取缓存。HTTP 仍为 `Cache-Control: no-store`，Nginx `proxy_cache off`，不是公开 CDN 或浏览器缓存。玩家精确查询及原始存档不缓存。
- 页面仍每 30 秒请求、隐藏时暂停。服务端快照最多 30 秒；两者叠加，业务变化到页面可见可能接近 60 秒，另计网络/查询耗时。“更新于”展示实际快照时间，页面注明缓存时长。
- 仅看板自己创建的数据库连接用启动参数 `jit=off`，保留最多 4 连接、SQL 5 秒超时及只读角色。没有 `ALTER SYSTEM`/`ALTER ROLE`，游戏 API 和其他数据库连接不受影响。
- 当前为单实例内存缓存，服务重启即清空，不新增 Redis 指标键。未来扩多实例时每实例会各自回源；如需全实例只回源一次，须另行实现共享缓存和分布式互斥。大数据量下仍需持续评估索引、查询计划和日汇总表，本改动不是无限并发或大规模容量保证。

## 正式服运行状态（实时概览）

实时概览新增独立的“正式服运行状态”区域，和原有玩家业务指标分别加载；状态探测失败不会清空活跃、留存或趋势数据。

- **服务探测**：固定读取正式服游戏 API 的 systemd 状态，并向本机登录接口发送缺少 code 的校验请求，确认返回预期的输入校验结果；不调用微信登录或发送消息。只表示检查时点的进程及该路径可用，不等于所有业务路径或微信上游完全正常。
- **数据库 / Redis**：用看板现有的只读数据库连接和 Redis 连接检查连通性；与游戏共享数据库/缓存实例，但不是玩家会话或全部游戏权限的端到端验证。
- **订阅提醒配置**：仅显示正式服两个发送开关的组合结果及正式版/体验版配置。读取受限字段，不返回凭据或其他环境配置；配置开关不代表微信仍有授权额度，也不等于消息已送达。
- **每天 09:00 定时任务**：显示定时器启用/运行状态、下一次执行时间和上次定时触发时间（均为北京时间）。`worker Result=success` 仅代表进程执行结果，不等于已发送；未定时触发时明确显示“尚未定时触发”。部署时的窗口外零发送检查不是实际日批次。
