## 统计口径

- 环境：正式小游戏，限定配置中的 appId。采用北京时间自然日。
- 队列归属：注册日期；只纳入 `game_users.first_login_completed = true` 的用户。
- D1、D3、D5、D7、D14、D20、D30 = 注册日后第 N 个自然日**当天成功登录**的人数 / 该注册日人数。不是 N 天内累计回访，也不是连续登录 N 天。
- 登录证据：`game_daily_logins` 的 appId、userId、activity_date 唯一记录；同一天多次登录只计一人。不能使用可变的 `last_login_at` 反推历史。
- 每天北京时间 **00:10** 汇总截至昨日的完整自然日。今天尚未结束的观察日不纳入日报。
- `pending`：未满观察期，显示“待统计”，不能当 0%。
- `uncovered`：观察日早于登录统计覆盖起点，显示“无覆盖”，不能当 0%。覆盖判定看观察日，而非注册日。
- `empty`：已满观察期且有覆盖，但该注册日新增为 0，显示“—（无新增）”，分母为 0。
- `complete`：完整观察且有新增；真实无人回访才显示 `0.00%`。
- 汇总留存为所有符合条件队列的“回访人数之和 / 新增人数之和”，不是每日留存百分比的简单平均。每个周期的成熟队列不同，分母可能不同，必须一并显示。

- `GET /h5dashboard/api/retention-report`：只读持久化 JSON，不触发数据库查询或汇总任务；不接受 appId、任意路径或日期覆盖。
- 显示报表截止日、实际生成时间、覆盖起点、计划更新时间、各周期加权留存与样本量、按注册日倒序的留存矩阵。

## 汇总和保存

新增 `dashboard/retention-report.mjs`、`scripts/build-retention-report.mjs` 及 systemd oneshot/timer 配置。

- 数据库沿用现有 `minigame_dashboard_app` 只读角色，不需要补钻 writer。
- 采用一个数据库时间戳和 `REPEATABLE READ READ ONLY` 事务，仅查询聚合数据，不保存玩家 UID、openid 或存档。
- 默认保留最近 **120 个注册日**的矩阵；数据历史还短的日期如实区分无新增与无覆盖。已保存的每日快照长期保留，后续可用于回溯，不能把不同快照的同一队列重复相加。
- 正式共享目录：`/home/ubuntu/.hermes/workspace/projects/minigame_server/runtime/analytics/retention`，独立于看板发布快照目录，切换或回滚代码不丢报表。
- 文件：`latest.json` 为最新完整快照，`history/YYYY-MM-DD.json` 为截至该日的完整快照。日期是**统计截止日**，不是生成日。
- 首次执行直接回算有真实记录的历史队列，生成一份当前截止日报；不会伪造过去某天已经生成过的日报。
- 同一天重复运行幂等；失败保留旧报表，禁止半成品覆盖。用原子发布、文件权限和并发保护防止读到部分文件。
- timer 使用 `Asia/Shanghai`、00:10、`Persistent=true`。机器恢复后补一次截至当前昨日的完整快照，跳过的日报生成日不会伪造，但最新快照包含范围内已经成熟的历史留存。

## 后续增长测算使用方式

1. 优先加载 `latest.json`，校验 appId、结构、统计截止日和生成时间。
2. 检查报表是否截至昨日；若落后，明确说明陈旧日期，不能声称是当前留存，也不能静默代替为旧的聊天测算值。
3. 读取各周期的回访人数、分母、成熟批次数及逐日变化；对 D20/D30 小样本单独提示。
4. 不把待统计/无覆盖/零分母当零；不对快照之间的相同队列重复累加。
5. 每日新增假设、起始日活、未来长尾形状与实际测得留存分开标注。离散周期报表无法唯一决定周期之间的留存，也不能证明尚未观察到的长期尾部。
6. 用不同长期尾部做条件情景；不得把先前“约75天”直接当成新报表结论。
